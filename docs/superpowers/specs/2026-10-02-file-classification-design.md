# QuantAgent 文件分类设计

## 目标与范围

将单向依赖、高内聚、低耦合、文档随代码维护落实到已有文件归属。保持模块化单体；本批仅规范导航、共享测试支持与六个测试路径试点。现有源码、API、配方、schema、权限、依赖允许表和 42 条存量豁免不改。

## 归属与边界

入口调用工作流和稳定契约；工作流编排业务模块的公开入口；业务模块依赖自身、ports 和必要契约；适配器实现 ports；bootstrap 组装注入。源码的函数内、类型检查、包根导出及动态加载均受边界约束。

产品代码保持当前包结构。自动测试分 unit、contract、integration、architecture；共享构造器和路径放 `tests/support/`；可执行替身放其 fakes；静态样本留 fixtures。未试点的平铺用例按主要能力登记，后续随整改迁移。每个实际独立目录有七项 README，不创建空目录。

QuantAgent 管理公共研究，OpenStock 管理私有档案、规则、决定与回证。私人现场脚本、原日志、密钥及数据库内容不进入公开仓库。学习只提议，更新由数据所属模块执行；更正追加而不覆盖原始记录。

## 兼容性与验收

共享 SEC 构造器保持现有载荷、哈希和默认时间语义。路径解析从指定文件所在目录查找最近完整仓库标记，与 cwd 无关，找不到即失败。六个测试迁移必须按模块名映射覆盖原 279 个唯一用例；只新增三个路径用例。两个 fake worker 原字节不变。

检查文档路径、实际源分支说明、全套与非零子目录测试、worker 离线协议、架构门禁。产物记录完整提交、环境、命令、真实结果、跳过与未测范围；本地通过不代表 CI 或生产通过。详情见 [实施计划](../plans/2026-10-02-file-classification.md)。
