# QuantAgent Plugin Contract v1

每个插件通过 `PluginManifest` 声明：插件 ID、精确版本、能力、输入契约、输出契约、权限、联网要求、重试安全性、运行方式与目录状态。Connector 是访问 API、MCP 或本地外部工具的插件类型，不建立第二套注册、授权或审计系统。

首批目录只允许 `plugin_catalog/catalog.json` 中的精选插件。目录状态分为 `verified`、`experimental`、`unverified` 和 `disabled`；未知插件不会自动加载，目录版本与运行实现不一致时启动失败。

## 当前执行边界（已实现）

- 读取插件必须通过本次运行允许的根目录检查。
- 修改既有文件必须同时通过读取根目录和单独的写入根目录检查；输出目录权限不会自动扩展到业务数据库。
- 报告只能写入本次运行的独立目录。
- 离线运行拒绝任何声明需要网络的插件。
- 在线模型还必须显式获得 `network:https` 和 `environment:read-secret` 权限；密钥只按环境变量名读取，不进入数据包或运行记录。
- 权限在创建运行目录前预检；缺少权限时不执行任何步骤。
- SQLite 适配器使用 `mode=ro`，不会迁移或修改原数据库。
- SQLite 结果回填默认只预览；只有 `apply=true` 且目标位于显式写入根目录时才开启事务。重复相同结果保持幂等，不同结果冲突时整体回滚。
- 只有插件明确声明 `retry_safe` 时，未来运行器才能考虑自动重试。

现有权限预检适用于受信任的内置插件。它不能阻止恶意进程内 Python 代码绕过接口，也不构成操作系统级沙箱。

## 能力与权限的区别

- 能力描述“插件做什么”，例如 `source.signal_history`、`model.daily_analysis`。
- 权限描述“一次运行允许它执行什么动作”，例如 `filesystem:read`、`network:https`、`process:spawn`。
- Skill 或 Agent 只能请求能力；真正的执行权限由运行器按动作批准。能力名称本身不授予文件、网络、密钥、进程或交接权限。

P1 起，有效权限必须是以下集合的交集：用户本次授权、部署策略、AgentManifest 请求、Recipe/Plugin 声明、可用凭据范围。任一方缺失即拒绝；交接不得扩大权限。

后续细粒度权限沿用命名空间并绑定资源范围，例如 `market:read`、`news:read`、`model:invoke`、`artifact:write`、`handoff:create`。资源允许名单、路径根、主机、工具名、凭据别名、费用和调用次数属于授权上下文，不得由模型输出覆盖。现有宽权限在迁移完成前按当前含义保留，不能假称已经实现细粒度代理。

## Tool Broker 与 Connector（P1/P4）

外部调用统一经过 Tool Broker：

1. 校验调用主体、运行 ID、插件/工具精确版本和动作参数结构。
2. 计算有效权限及资源范围，检查超时、调用次数和费用预算。
3. 在模型上下文之外按凭据别名注入最小凭据。
4. 执行允许名单中的固定服务器和工具；禁止模型安装包、修改允许名单或选择任意目标。
5. 校验响应大小、结构、契约和来源，保存必要的请求摘要、结果哈希、时间和失败原因。

MCP 只提供工具发现和调用协议，不提供数据授权或安全保证。服务器上的全部工具不得默认暴露给 Agent。浏览器或不可信材料中的文字不能直接转为工具调用。

## 执行方式

进程内插件只适用于轻量、可信且依赖兼容的能力。第三方发现阶段只读取静态清单，不导入模块、不运行安装脚本，也不执行 Skill 包中的脚本。

独立进程插件必须声明 `process:spawn`，使用绝对可执行文件和参数数组（禁止 shell 拼接），并对可执行文件、worker 与输入路径执行读取根目录检查。主机限制超时、响应体和日志大小，校验协议版本、请求 ID、结果契约与输入哈希。子进程只继承运行所需的最小环境变量集合；独立虚拟环境解决依赖冲突，但不提供操作系统级沙箱。

首版只运行受信任的精选实现。开放第三方可执行包前，必须另行验证文件、网络、进程、资源和密钥隔离；路径检查或虚拟环境不能被标为完整沙箱。

## 模型插件（P1）

模型选择按能力协商，而不是只匹配模型名。至少分别记录并检查文本生成、结构化输出、工具调用、上下文容量和离线回放能力。运行记录保存 Provider、实际模型标识、参数、Prompt/Skill 版本、输入/输出哈希、调用时间、费用和是否使用录制响应。

模型提出的动作必须再次经过授权；结构正确的模型输出仍是不可信建议。切换模型、Prompt 或结构化输出模式会使相关兼容证据失效，必须重跑对应夹具。

## 目录状态与证据边界

`verified` 继续只表示仓库政策规定的离线测试通过。`experimental` 适配器可以进入精选目录用于受控联调，但不能因协议 worker 或固定样本通过而宣称真实外部服务、数据语义、策略收益、沙箱安全或任意组合已验证。
