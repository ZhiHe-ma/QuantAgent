# 功能分支说明

## 职责与边界

每条功能分支保留一份变更记录，描述本次改动，不代替功能 README 的当前状态。

## 文件导航

当前整合入口：[I003](i003-integration-acceptance.md)，汇总实际目标、能力覆盖和固定版本验收；各批历史通过其链接查阅。已有记录：[架构门禁](architecture-guardrails.md)、[文件分类](file-classification.md)。新说明放在本目录，文件名对应功能。

## 对外接口

首个 JSON 块声明 branch（完整源分支）、base_commit（40 位 SHA）、components（受影响能力 ID）和 readme_unchanged（能力 ID → 无需更新的具体理由）。

正文保留七节：目标与非目标、涉及模块、接口或数据变化、新增依赖、测试证据、回滚方式、遗留问题。验收写命令、环境、提交、实际结果和未测范围；允许有理由的“未运行”或“不适用”。

## 依赖规则

能力 ID 来自[登记表](../architecture/components.json)，边界见[架构规范](../ARCHITECTURE.md)；正文链接当前规范，不复制一套规则。

## 数据与权限

只记录可公开的变更及验收结论，原始私有日志留在受控本地目录。

## 测试与验收

[门禁](../../tools/architecture/README.md)按 PR 实际源分支匹配说明；目标分支推送检查本次变更的历史说明及文档完整性。

## 已知限制

检查只能验证格式与覆盖，文档真实性仍需人工审查；历史记录中的结果仅适用于其版本与范围。
