# Compatibility Policy

兼容声明只覆盖实际测试过的精确组合，不外推到整个版本区间，也不暗示上游官方认证、研究正确、策略盈利或安全沙箱已经成立。

## 兼容维度

- 结构：必填、类型、枚举、空值、未知字段、单位、时区和版本。
- 消费方交互：真实使用的请求/响应、错误码、增删字段和重试语义。
- 语义：标的、市场、事件/发布/可用/决策时间、报价币种、复权和收益尺度。
- 历史：固定输入、迁移副本、Point-in-Time、重放、幂等和模型/Prompt 变化。
- 故障：超时、非法 JSON、HTML 冒充数据、SQLite 锁、断网、磁盘失败和部分响应。
- 权限与注入：路径越界、密钥泄漏、伪造工具/交接文本、越权目标、重复请求和预算超限。
- 完整配方：真实连接顺序、输出、取消、失败、恢复及版本替换。

## 证据等级

| 等级 | 含义 | 可以声明什么 |
| --- | --- | --- |
| `static` | 文档、Schema、许可证或源码静态核对 | 结构/边界已定义，不代表可运行 |
| `offline_fixture` | 固定夹具与录制响应 | 指定离线行为可重放 |
| `protocol_stub` | 协议替身/假 worker | 主机协议、错误隔离和边界行为通过 |
| `real_dependency_fixture` | 真实依赖读取固定样本 | 精确环境与固定样本兼容 |
| `live_interface` | 真实外部接口的受控调用 | 该账号、版本、时间和请求范围联调通过 |
| `end_to_end` | 完整配方及授权链 | 该精确组合端到端可用 |

`verified` 继续表示仓库内离线测试通过；它不是外部认证。跳过真实依赖测试必须记录为 `skipped`，不能并入通过数或写成真实集成已验证。只有 Provider 参与验证的消费方契约测试才能称为双方契约证据；本地录制样本只能称为适配器回归。

## 版本与失效

- 契约主版本变化视为破坏性变化；新增可选描述性元数据可保持同一主版本。
- 精选目录中的插件实现版本必须与目录版本一致。
- Agent、Skill、Recipe、Plugin、模型、Prompt、上游依赖和 Schema 都记录精确版本，不使用通配范围代表已验证。
- 单插件通过不代表任意组合通过；只有配方级测试通过的组合可以称为已验证套餐。
- Agent 换模型、Skill/Prompt 改动、插件换上游版本、语义转换改变、权限策略改变或夹具哈希变化，会使相关证据失效并触发重跑。
- 未验证、信息损失、样本不足和无法评价必须原样显示。
- 运行产物按 `run_id` 保留；停用或退役实现不删除历史包和报告。退役记录包含替代版本、最后验证版本、迁移说明和保留期。

## 兼容报告最低字段

每份报告包含：代码提交和树哈希；操作系统与 Python；Agent/Skill/Recipe/Plugin/契约/Schema/模型/上游精确版本；依赖锁定方式；数据、Prompt、配置和夹具哈希；执行时间；证据等级；通过、失败、跳过；命令或工作流；范围、信息损失和已知限制。

私有生产数据只保存受控哈希和脱敏/合成 Golden Fixtures；不能因测试需要公开原始新闻、账户或商业数据。报告名称使用“版本化兼容报告”，明确为项目自测。
