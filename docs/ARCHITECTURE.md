# QuantAgent 有效架构与治理状态

当前状态：**部分符合**。基线为远端 main 提交 ccded244593942fc6de7c10983d6b0f795c36a47；35 个现有生产模块包含 42 条具体违规及两组静态依赖环。门禁新增代码属于开发工具，不改变业务接口或运行时行为。

## 四条硬约束

单向依赖、高内聚、低耦合、功能文档随代码维护。反馈闭环可以成立，源码依赖不能成环。返回结果不等于反向源码引用。

## 依赖与公开接口

入口调用工作流及稳定契约；工作流调用业务公开入口；业务只引用自身、所属 ports 和必要稳定契约。适配器实现对应 ports，bootstrap 组装并注入实现，指定启动入口才能调用 bootstrap。业务模块默认互不直接导入。contracts 不依赖工作流、具体适配器或数据库/模型 SDK。包根导出保留兼容，但内部代码不能借其绕过边界；函数内、TYPE_CHECKING、动态加载与跨能力私有导入均受检查。

现有平铺源码按 [能力登记](architecture/components.json) 逐项归属，README 提供入口导航。登记不是移动文件，也不是对混合旧代码符合规范的声明。每个实际独立功能目录有七项 README；新目录必须登记。不会预建草案中的空业务目录。

## 数据归属与学习闭环

QuantAgent 拥有公共证据、来源、研究结果和运行审计；OpenStock 拥有用户私有档案、规则、决定及回证，仍通过版本化接口协作。禁止 Python 模块绕过所属模块直写 OpenStock 私有数据库。账户隔离不能由静态 import 检查证明，后续数据业务改动必须增加对应集成验收。

未来学习流程：读取版本化经历和回证 → 形成候选经验 → 验证并取得既定用户确认 → 由数据所属模块更新。learning 不直接覆盖 profile，不自动改变规则或权限。原始决定及当时理由保留，更正追加记录；回证中的事实、推测、反证与未知分别展示。首批不实现学习业务、模型训练或交易。

## 存量与门禁

[精确基线](architecture/legacy-baseline.json) 每项保存规则、引用边/成员、理由及 [整改任务](architecture/remediation.md)。禁止通配豁免；与目标提交登记比较只能减少。已清除的违规不得重新登记；新环、新违规或循环扩大均失败。首次引入以精确目标提交源码核对，不能把新代码造成的问题作为旧基线。

Import Linter 检查禁止引用、独立性、分层与同级循环；标准库 AST 补充顶层脚本、能力覆盖、私有引用、动态加载及原始环图检查。类型检查导入不排除。检查工具只静态读取产品代码，不执行产品、不联网。官方工具配置和原始图一同保存到显式报告。

能力的允许依赖指直接源码引用，允许契约再引用已登记的其他契约。Import Linter 禁止引用契约启用 allow_indirect_imports，分层、独立性和循环检查仍独立生效。嵌套业务目录中的 runtime/tests 不按顶层运行产物排除；对未登记本地导入目标也报错。普通点号导入后的包根导出访问计入依赖。别名保守保留全部导入绑定，避免局部别名覆盖掩盖违规；同名别名导致的保守误报需拆开命名，不可添加广泛豁免。反射、运行时赋值和任意代码生成仍须人工检查。

业务和契约层仅默认允许标准库；纯外部包须逐项登记 external_dependencies（当前 jsonschema）。数据库/网络/模型包另受禁止引用约束。已有能力新增外部依赖需先单独审查其政策，不能通过本次代码顺手扩张。独立 Skill 按能力单独登记，directory_roots 自动发现新增目录，所属 README 必须随变更同步或逐项解释。删除能力按目标提交原归属计算受影响范围；历史分支说明保留原能力名称。

README 描述当前状态；功能分支说明记录本次目标、非目标、模块、接口/数据变化、依赖、测试证据、回滚与遗留问题。变更不影响 README 时，必须按受影响能力提供理由；不存在的 README 无法豁免。PR 用源分支匹配，目标分支合并推送检查本次变更说明。

## CI 与人工审查

CI 使用 Python 3.12，在 Windows/Linux 分别运行全部离线测试和 architecture 检查。GitHub 设置中需要将 `Architecture / Python 3.12 / ubuntu-latest`、`Architecture / Python 3.12 / windows-latest` 以及原有两项测试检查设为 main 必需检查，并要求人工审核；CODEOWNERS 覆盖治理工具、规则、文档和 workflow。仅提交 workflow 或 CODEOWNERS 不等于远端保护已生效。设置状态在分支验收记录中单列。

机械检查不能判断职责是否合理、文档是否真实或运行时是否越权；人工必须审查这些语义及豁免理由。代码所有者自己提交的 PR 需要另一位有权限的审阅者才能满足有效审批，不能自己审批自己。源码与文档检查通过后，只能称为首批治理门禁建立；全部存量清零后才可声明四条约束全部符合。

## 验证与兼容

从仓库根运行 `python -m unittest discover -s tests -v`；运行 `python -m tools.architecture --base-ref <目标提交> --branch <完整源分支> --report artifacts/architecture/report.json`。完整结果按命令、Python/OS、代码版本、实际结果、跳过项与未测范围记录于 [分支说明](features/architecture-guardrails.md)。

首批保留 Python 导出、CLI、HTTP 契约、固定配方及原有审计；不迁移数据库，不修改私人资料，不重定义研究或信号语义。后续源码重构逐批回归兼容路径；本地、CI、部署与生产证据分开填写。
