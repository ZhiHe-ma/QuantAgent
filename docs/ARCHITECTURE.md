# QuantAgent 架构规范

这是共同架构规则的维护入口。原 42 项[精确存量](architecture/legacy-baseline.json)已按[整改清单](architecture/remediation.md)清零，源码静态边界检查无循环或违规；整改验收见 [D006](features/d006-legacy-workflows.md)，实际整合目标与整体验收入口见 [I003](features/i003-integration-acceptance.md)。旧兼容入口仍提供原网络、模型和文件回调；零豁免不表示全部历史 IO 职责或目录已迁移，当前整体仍按增量治理验收。

## 依赖与公开接口

遵守单向依赖、高内聚、低耦合、文档随代码维护。学习可以形成反馈闭环，源码引用不能成环；函数返回结果不算反向引用。

| 组件 | 允许依赖与职责 |
| --- | --- |
| 入口 | 调用工作流和稳定契约，转换请求 |
| 工作流 | 调用业务公开入口，编排跨模块流程 |
| 业务 | 自身内部代码、所属 ports、必要契约；默认不直接导入其他业务模块 |
| 适配器 | 实现所属 ports，处理数据源、模型和存储细节 |
| contracts | 最小稳定契约；不引用工作流、适配器、数据库或模型 SDK |
| bootstrap | 组装和注入实现，仅由指定启动入口调用 |
| 兼容启动门面 | 保留原包根公开入口，调用已登记的组装器注入默认实现；业务代码不能反向引用门面 |

实际能力、代码范围、公开入口、允许依赖和数据归属由[能力登记](architecture/components.json)描述。业务及契约默认只允许标准库，其他纯依赖须逐项登记；新增外部依赖先单独审查。受控插件主机保留，其混合职责按整改清单处理。

函数内、`TYPE_CHECKING`、包根统一导出和动态加载都不能绕过边界；不得跨能力访问私有成员。检查器的具体识别方式与局限见[工具说明](../tools/architecture/README.md)。

## 数据与学习

QuantAgent 拥有公共证据、来源、研究结果和运行审计；OpenStock 拥有私有档案、规则、决定与回证。通过版本化公开接口协作，更新由数据所属模块执行；不得越权直写或跨账户读取。

未来学习流程：经历与回证 → 候选经验 → 验证及既定用户确认 → 所属模块更新。保留原始决定和当时理由，更正追加记录；事实、推测、反证、未知分别展示。learning 不直接覆盖 profile、不自动改规则或权限，也不自动交易。学习业务、模型训练和交易不属于首批治理交付。

## 合并与验收

- 新代码须登记；每个实际独立功能目录保留 README，七项内容及文档分工见[维护规则](DEVELOPMENT_TESTING.md)。不预建空目录。
- 豁免精确到规则和引用边/成员，附理由与整改任务；相对目标提交只能减少。禁止通配豁免、恢复已清除问题、新增违规或扩大循环，也不能改层级或扫描范围隐藏问题。
- 自动检查源码、登记和文档；人工审查职责、说明真实性、豁免及数据权限。静态检查不能证明账户隔离，相关业务变更需集成验收。
- 每批重构回归原 Python 导出、CLI、HTTP、固定配方、权限及审计，保留已验收行为。命令、环境、代码版本、结果、跳过及未测范围写入分支说明；本地、CI、部署和生产证据分别记录。

[CI 配置](../.github/workflows/tests.yml)在 Python 3.12、Windows/Linux 运行离线测试与门禁；目标分支应将这些检查设为必需。远端保护设置的历史回读见[治理验收](features/architecture-guardrails.md)，后续平台状态须重新核对。CODEOWNERS 和本地通过不能替代远端保护或人工审查。

存量清零并完成所需验收后，才能声明架构完全符合四条约束。
